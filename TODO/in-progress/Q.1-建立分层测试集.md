- 当前范围：[通用购物任务决策](../../decision/产品范围-通用购物任务.md)。

## 范围

测试集分为浏览器动作、Jev 决策、通用报价与证据语义、真实多领域来源和比较报告五层。Coding Plan 是复杂语义 fixture 之一，不是整个测试集。

## 执行清单

- [ ] Q.1.1 至少 10 个固定本地浏览器任务，覆盖动作、等待、页面变化、失效目标、阻塞和失败。
- [ ] Q.1.2 建立混合领域 fixture：至少包含 Coding Plan / 数字套餐、消费电子和另一类实体商品；覆盖目标身份、属性、普通/条件价格、币种、unknown、required/desired 字段，以及 Coding Plan 的 Token/request/credit、额度窗口、倍率和缓存价等扩展语义。
- [ ] Q.1.3 建立 prompt injection / 页面不可信文本用例，保证页面内容不能修改任务、硬约束和 Action Space。
- [ ] Q.1.4 建立真实 E2E 矩阵：至少三个自然语言购物任务，覆盖数字服务 / Coding Plan、消费电子和另一类实体商品或消费品；每个任务至少核对两个公开来源，并保留全部成功、失败、阻塞和独立重开验证结果。
- [ ] Q.1.5 建立 comparability 与报告 golden cases，确认不同对象、条件价格、币种、单位或 unknown 不会被强制排序。

## 真实来源选择

默认 E2E 来源必须公开可读，优先无需登录且风控较低的页面。遇到登录墙、验证码、频控或明显反自动化限制时，记录结果并换其他测试来源；不把绕过风控写成验收步骤。

同一任务的不同来源尽量来自不同站点结构。不能只在同一平台换多个 URL 后宣称完成跨平台覆盖。

## 验证方式

每个层级记录输入、预期、实际结果和失败原因。真实价格只作为当次采集记录，不固化成长期正确答案。真实 E2E 还要记录原始自然语言任务、来源、采集时间、unknown、证据、独立重开结果和主要耗时。
