状态：in-progress（未开始）。建立日期：2026-09-23。

- 产品规则：[Coding Plan 比价规则](../../DOC/Coding%20Plan%20比价规则.md)。

## 范围

M4.1 把 M1/M2 的通用价格证据升级为 Coding Plan 领域数据。重点不是“把所有套餐换算成一个数字”，而是先正确区分对象、价格语义、额度单位和时间窗口，再对真正可比的记录做确定性计算。

## 执行清单

- [ ] M4.1.1 新增 Coding Plan 领域类型，例如 `PlanOffer`，至少表达 provider、plan、supported models、billing mode/period、price type、eligibility、quota、usage rules、source、observedAt 和 evidence。
- [ ] M4.1.2 任务支持 `requiredFields` 与 `desiredFields`。必需字段全部有证据才可成功；期望字段缺失保持 unknown。
- [ ] M4.1.3 区分常规价、促销价、首购价、续费价、年付总价/月均展示价和按量 Token 单价。不同语义不合并。
- [ ] M4.1.4 额度保留 metric、amount、window、resetRule。Token、request、credit、不同时间窗口和模型倍率不能只凭数字互换。
- [ ] M4.1.5 缓存价格、峰谷倍率、模型倍率和适用限制没有证据时保持 unknown；未知值不能写成 0、免费或无限。
- [ ] M4.1.6 定义确定性的 comparability 检查。模型/模型集合、计费方式、价格语义、币种和任务必需条件不一致时，不进入同一排序。
- [ ] M4.1.7 保留现有 `Offer` 作为 M1/M2 兼容接口；迁移或替换必须由测试证明，不在文档中假装已经完成。

## 验证方式

使用本地 fixture 覆盖：相邻模型名、按量 vs 包月、首购 vs 续费、月付 vs 年付月均、Token/request/credit、5 小时 vs 周窗口、倍率未知、缓存价未知、混合币种和字段缺失。

## 完成条件

- [ ] 领域类型和 comparability 规则有独立测试。
- [ ] 模型不承担金额算术、额度换算或最终排序。
- [ ] 未知项不会进入确定费用或最低价结论。
- [ ] 同步接口文档、roadmap 和 TODO 索引。
- [ ] 完成后移入 `TODO/done/`。
