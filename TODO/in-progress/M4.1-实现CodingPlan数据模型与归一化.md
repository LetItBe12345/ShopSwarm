## 范围

M4.1 把 M1/M2 的 `model + specs + seller` 兼容接口升级为领域无关的购物研究契约。核心是表达“用户要找什么、哪些条件必须满足、页面实际观察到了什么、哪些结果可以比较”。Coding Plan 的套餐、额度和倍率是扩展字段，不作为核心模型的唯一形状。

## 执行清单

- [ ] M4.1.1 定义通用 `ResearchTask` 或等价任务结构，保留原始自然语言目标，并表达来源范围、硬约束、偏好、`requiredFields` 和 `desiredFields`。
- [ ] M4.1.2 定义通用报价 / 候选结果结构，至少表达目标身份、可验证属性、seller/provider、价格与币种、价格条件、source、observedAt、evidence 和领域扩展字段。
- [ ] M4.1.3 `requiredFields` 全部验证后才允许成功；`desiredFields` 缺失保持 unknown，不因缺失而无限浏览。
- [ ] M4.1.4 普通价、促销价、首购价、会员价、续费价、年付月均等价格语义保持不同；页面没有明确条件时不推断。
- [ ] M4.1.5 领域特有属性保留原始语义。例如实体商品的尺寸/容量/版本，Coding Plan 的 Token/request/credit、额度窗口、倍率和缓存价；没有明确依据不跨单位换算。
- [ ] M4.1.6 未知价格、属性、费用、额度、倍率和限制保持 unknown，不能写成 0、免费、无限或默认值。
- [ ] M4.1.7 用确定性代码判断 comparability。目标身份、硬约束、价格语义、币种或必要领域属性不一致时，不进入同一排序。
- [ ] M4.1.8 保留现有 `ShoppingTask` / `Offer` 作为 M1/M2 兼容接口；迁移或适配由测试证明，不做无验证的大爆炸重写。

## 验证方式

至少用三类本地 fixture：

1. Coding Plan：按量 vs 包月、首购 vs 续费、Token/request/credit、不同额度窗口、倍率和缓存价 unknown。
2. 消费电子：相邻型号、容量/尺寸/版本、卖家、普通价与条件价。
3. 其他实体商品或消费品：验证核心模型不依赖“型号/Token/套餐”语义。

同时覆盖混合币种、字段缺失、required/desired 和不可比条目。
