- 已确认方向：[M2.4 决策](../../decision/M2.4-阶段验收.md)。

## 范围

M2.4 负责验收 M2 已实现的浏览器动作循环、Jev 约束和完成检查，并把后续真实领域固定为 Coding Plan / LLM 中转套餐。M2.4 不要求现在完成 M4 的 `PlanOffer`、额度换算或最终排序。

## 执行清单

- [ ] M2.4.1 固定样例能区分不同模型标识、按量单价、套餐价格和额度；缺价、条件优惠、未知额度和伪完成不会被判为已确认费用。
- [ ] M2.4.2 至少建立一份可复现的 Coding Plan 用例记录，包含来源、核对日期、成功与失败尝试、未知项和任务要求。
- [ ] M2.4.3 模型选择的动作或目标不在当前有效集合时，执行器拒绝操作；Jev 返回后页面或目标变化时也拒绝执行。
- [ ] M2.4.4 单条命令超时、取消、明确阻塞、登录、验证码、频控和服务失败均返回结构化原因。
- [ ] M2.4.5 明确记录当前 M2 数据模型的限制：它可以验证动作循环和基础价格证据，但尚不能完整表示 Coding Plan 的额度窗口、续费语义和倍率。
- [ ] M2.4.6 冻结 required / desired 字段的设计规则并写入领域契约：必需字段缺失不能成功，期望字段缺失保持 unknown；实际通用字段驱动实现纳入 M4.1，不在阶段验收里伪装成现有能力。
- [ ] M2.4.7 Jev 与 LLM baseline 使用相同任务条件、Action Space 和独立检查；无法取得费用时标为未知。
- [ ] M2.4.8 真实来源只读。出现风控或页面不可访问时记录失败，不以绕过风控作为阶段通过条件。

## 验证方式

复跑本地正确/错误报价、非法目标、页面变化、明确阻塞、命令超时和取消；再选择至少一个公开 Coding Plan 或中转套餐来源做只读记录。真实来源可以失败，但必须保留失败原因和页面/接口边界。
