## 范围

让 DSH Lead Agent 把同一个 Coding Plan 比较任务分发到多个来源。ShopSwarm 不自建 Agent 调度器，只管理本插件拥有的浏览器、HTTP 请求和并发资源。

## 执行与验证记录

2026-09-23，在从最新 `main` 建立的独立 worktree 中实现。`skills/shopping-research/SKILL.md` 规定 Lead 使用 DSH `subagent` 的 `spawn` 后端分发相同模型、计费需求和字段要求；一次性 headless 任务使用 `run_in_background: false` 等待子任务结果。`src/resource-limit.ts` 和 `src/index.ts` 对浏览器诊断、手动浏览和单来源研究工具共用进程内 FIFO 并发限制，默认 2，可通过 `maxConcurrentBrowserTasks` 配置；等待时取消会移除队列项，工具结束或清理后释放槽位。此上限按工具调用计，一次 `shopswarm_research` 在独立重开复核阶段最多可能同时有两个浏览器会话；不限制 DSH Subagent 本身数量，也不跨多个 DSH 进程共享。Agent 与 callId 继续作为浏览器资源 owner；完整来源和证据关联属于 M3.2。

本机使用 Node.js 24.21.0、pnpm 11.7.0、agent-browser 0.38.1。类型检查、14 个测试文件共 56 项、构建均通过；`tests/resource-limit.test.ts` 覆盖上限、FIFO、重复释放、等待取消和非法配置。根入口 `pnpm check` 因当前全局 pnpm 报 `packages field missing or empty`，已分别执行其中的 typecheck、test、build 三步。DSH 参考仓库为 `https://github.com/deepseek-ai/deepseek-harness.git`，本次核对提交 `00102833dfaee1da9f48a3a8eae9d34005a75218`，检索日期 2026-09-23；DSH 运行版本为 `0.1.7-alpha.2`。

真实来源：2026-09-23 晚间在独立 headless 会话访问 [智谱 Coding Plan 套餐概览](https://docs.bigmodel.cn/cn/coding-plan/overview) 和 [星模 XModel GLM 5.3](https://www.modelxing.com/zh/models/glm-5-3)，页面均可读，前台 `DISPLAY` 未设置、未连接用户 Chrome；会话关闭后 `agent-browser session list` 为空。OpenRouter GLM-5.3 页面两次加载超时，未列为已验证来源。

独立 DSH `headless` profile 安装当前 Bundle 后，先在同一 Lead 回合并行发出两个 `subagent` 前台调用，再按相同输入顺序调用两个来源。两种运行均实际调用 `shopswarm_research`，共同条件为 `model=GLM-5.3`、公开价格与计费条件、相同字段集合和只读约束。顺序运行的两个子任务返回同一 JSON 字段结构；并行运行的子任务保留了同一工具返回结构，但 Agent 最终转述为文字，因此 Skill 已补充要求只返回 JSON 对象。并行两次有效工具调用分别在 21:43:41.670、21:43:42.433 发出；上限设为 1，结果分别在 21:43:54.889、21:44:10.591 返回，耗时 13.22 秒和 28.16 秒。顺序调用分别耗时 11.95 秒和 20.76 秒。队列是否占用槽位的精确行为由 `tests/resource-limit.test.ts` 验证；DSH 时间记录仅显示并行调用中的等待现象。

四次真实研究结果均为 `blocked/no_progress`。顺序运行中，智谱来源实际导航到 `https://bigmodel.cn/pricing`，缺少明确标价或币种证据；星模 XModel 停在模型页 `#pricing`，缺少符合当前验证器要求的型号证据。M2 的 `ShoppingTask` / `Offer` 无法完整表达 Coding Plan 的价格类型和额度规则，本任务只验证分发、结构和资源限制，不宣称已核实套餐价格。首次并行运行曾因把未知规格写成 `null` 被工具拒绝，子任务改用 `specs:"[]"` 后完成；Skill 已明确这一输入要求。真实原始 DSH 会话和浏览器日志仅存于本机临时目录，未加入仓库。来源归属、整体取消和局部结果汇总继续由 M3.2 验证。
