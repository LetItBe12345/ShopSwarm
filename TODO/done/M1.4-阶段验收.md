## 执行与验证记录

2026-09-23 在 Ubuntu 24.04、Linux x86_64、Node.js 24.21.0、pnpm 11.7.0、agent-browser 0.38.1 上执行。验收只打开 M1.3 本地固定页面，没有调用模型，也没有打开京东或天猫。

- M1.4.1：[验收测试](../../tests/m1-acceptance.test.ts) 对打开、快照、填写、点击、按键、滚动、等待、选择、后退和关闭连续成功 3 次。失效元素引用 3 次都返回 `stale_element_reference`，消息为 `element @e15 is not part of the current page snapshot`。
- M1.4.2：两个会话分别打开搜索页和规格页。向第一个会话填写的文本没有出现在第二个会话。关闭第一个后，第二个仍能选择容量。
- M1.4.3：正常关闭和等待过程中取消后，本项目会话从 `session list` 消失，对应临时 Profile 目录删除。同一 socket 目录里预先打开的外部会话和它的 Profile 仍在。取消结果是 `uncertain/cancelled`。
- M1.4.4：验收在临时目录生成带标记 cookie 的 Profile，不读取用户正在使用的 Chrome。agent-browser 按 Profile 名 `Default` 复制后再读取，标记 cookie 能从副本读到，副本目录随后删除。源 Profile 的文件内容和 `Crash Reports` 符号链接保持不变。真实店铺登录没有执行，不写成支持承诺。本次 headless 运行前后，`_NET_ACTIVE_WINDOW` 都是 `0x3800043`。这只是这次记录，不保证以后不改变焦点。
- M1.4.5：同一次运行分开记录浏览器启动 159 ms、启动后的单次快照调用 44 ms、延迟文本等待 236 ms。没有时延上限。

Chrome 复制 Profile 后，crashpad 仍会把报告写回源目录的 `Crash Reports`。验收在计算基线前把该目录换成临时目录的符号链接，因此这份写入不改变源 Profile 的文件内容。

DSH 和 agent-browser 不继承终端代理。本次验收检查到 ShopSwarm 拉起的 Chrome 命令行没有 `--proxy-server`。策略见 [安装与运行](../../DOC/安装与运行.md#代理)。

pnpm check
