# 修改后 ShopSwarm、直接浏览器与 Chrome Profile 对比

本文记录当时冻结的三工具构建；后续单工具 adapter 以当前设计说明和后续验证记录为准。

## 结论与适用范围

2026-09-30 完成用户指定五用例、三组各一次，共 15 次真实 DSH CLI 运行。运行期间没有人工修改 prompt、接管浏览器或补发指令。逐项审阅真实页面证据，不把 CLI exit=0、模型自称 complete 或插件接受报告当成任务成功。

默认访问下，直接 CLI 新会话和 Profile 组均取得 4/5 个用例的报价证据；ShopSwarm 工具本身取得 3/5。ShopSwarm 组的 Aeron 最后通过直接 CLI 取得报价，单列为 fallback，不能算插件报价成功。Aeron 规格不完整、Thomann 新品条件没有直接证据，报价取得不等于完整任务通过。

本轮没有显示 Chrome Profile 的稳定速度或可用性优势。Profile 没有解决 Aeron 的字体请求停滞，也没有单独解决 BIKE24 的 Access Denied。五页均为公开商品页，没有验证登录后购物场景。当前建议保留独立新会话默认值；Profile 只读复用是后续可选方向，本轮没有给 ShopSwarm 新增该功能。

三组均未调用 Jev。本轮无法判断 Jev 提速，也不能证明默认 40 个动作候选优于 100 个。此前一次真实 Jev 调用只证明 API 路径可用，见[第一轮验证](验证记录-2026-09-30-来源Agent主导.md)。

## 版本与方法

- 工作分支：`fix/shopping-evidence-and-jev-context`。开始时已核对本地 `main` 与 `origin/main`，均为 `c4b166176d76a4efad1d5304993e1d5b0fd4ca3c`。本轮实现尚未提交、推送或合并。
- Node.js 24.21.0、pnpm 11.7.0、DSH 0.1.7-alpha.2、agent-browser 0.38.1；ShopSwarm 本地未发布版本 0.3.0。
- 冻结安装包 SHA256：`0f1d1d692537f836f7ffa329687163946da54af37f5228b548c28fd91e1b2916`。评估中未修改插件实现或 Skill。
- DSH 实际日志模型标识为 provider `deepseek-official`、model `deepseek-flash`；不据此断言具体模型发布代次。
- 每个用例三组自然语言 prompt 相同，使用 DSH 原生同步来源 Subagent。Agent 自主选择工具、恢复与汇总；ShopSwarm 可按需使用 Jev，也可 fallback。
- 两个直接 CLI profile 不加载 ShopSwarm bundle；Profile 组通过 agent-browser 启动配置指定 `Default`。这是三种运行环境的比较，没有在 prompt 中禁止某个已加载工具。
- 五用例依次为 Aeron、iPhone、Thomann、BIKE24、Samsung；每个用例轮换三组起跑顺序。
- DSH 与浏览器直连，去除继承代理。独立 headless，`--headed false --auto-connect false`，不连接用户 Chrome，不购买或支付。
- 来源 Agent 和 Lead 均可能重复核验。同一工作区可见历史文件，未做盲测；只有本次来源和采集时间对应的证据计入结果。

这是一次三组单轮观察，不是历史 TODO 的 30 次、每组重复三次 benchmark。站点状态、模型输出、缓存、重试策略和 DSH sandbox 都可能影响结果，不能把耗时差直接归因于 Profile、Jev 或插件本身。

## 实际错误与原因

1. **会话所有权提示不准确。** `run.ts` 总输出 `handoff.owner='subagent'`，注册表实际按调用者 Agent 身份绑定。Lead 自己启动来源后，子 Agent 不能接管该 handle；默认一个浏览器槽又导致子 Agent 新建来源 `resource_busy`。Aeron、BIKE24 均出现。独立 CLI 不占插件的 ResourceLimit，模型把 CLI 说成占槽原因是错误解释。所有权校验需要保留，改进的是工具提示和调用流程。
2. **页面恢复路径不对等。** Aeron 起点 404，字体请求令页面解析停滞；Thomann 导航超时后已有可读 DOM。直接 CLI 用 eval、读取及字体请求调整继续研究。插件也在 Thomann 重开来源后取得报价，但失败输出和恢复步骤不够清楚。超时不应被模型直接当成永久不可用。
3. **报价报告提交脆弱。** Samsung 完整报告把 AX 多行原文压成不连续字符串，出处校验拒绝两次。最小 partial 报告接受后来源已关闭，再补全会遇到过期 handle。校验引文真实性有必要；应改善引用方式和“提交即关闭”的说明，不能恢复硬编码商品匹配或简单移除出处检查。
4. **DSH / 模型等待影响端到端速度。** Aeron 插件组第一个来源子会话某步骤约 657 秒，只输出两枚 reasoning token、没有最终文本；Lead 后来第二次委派才取得返回。本轮其他来源均有返回，不能写成“主 Agent 始终收不到子 Agent”。readonly HOME、socket 和 daemon 生命周期也令直接 CLI 增加恢复步骤。
5. **重复核验和无收益重试。** 多组 Lead 与来源分别重新浏览；BIKE24 插件组约六分钟 HTTP 轮询仍为 403。来源 Agent 主导没有自动避免重试膨胀。后续应从指令和可见会话状态减少重复，而非加商品语义硬规则。
6. **语义判断仍会出错。** Thomann 新品、库存、卖家身份和 Samsung 条件优惠存在过度推断；把难题交给 Subagent 并不等于正确性已解决。保留 observed / inferred / unknown 与 Lead 复核仍然必要。

建议先处理所有权提示、提交报告体验和可读页面的恢复接口，再考虑 Profile 支持与 Jev 对照。以上是评估后的建议，本轮未实施第二轮代码改动。

## Profile、焦点和清理

agent-browser 0.38.1 安装包 README 的 Chrome Profile Reuse 说明：名称 `Default` 会被复制到临时目录，浏览器使用副本；路径参数则属于持久自定义 Profile，是不同模式。参考[上游仓库](https://github.com/vercel-labs/agent-browser)，检索日 2026-09-30，接口以本机固定安装版本为准；本轮本地外部参考仓库缺失，未把其路径当运行依赖。

Profile 组保留指定启动配置，没有自行选择其他 Profile；实际登录态继承和各次 Chrome 进程加载副本未独立核验。因此结论仅限“配置 Profile 复用的这组运行”，不能承诺登录一定继承。

运行前后抽查原始 `Local State`、`Default/Preferences`、`Secure Preferences`、`Cookies`、`Login Data`、`Web Data` 六个文件的 SHA256 与大小，全部相同。这是抽查，不是完整 Profile 审计。此前复制机制的夹具测试另见单元测试。

15 次结束时 agent-browser session 列表均为空，X11 焦点监测没有记录变化。监测值一直为 0x0，不能证明全部原生 Wayland 焦点行为。没有连接用户窗口，也没有为了测试切到前台。

## 日志与复现

私有记录：[`runtime/subagent-evaluation/comparison/`](../runtime/subagent-evaluation/comparison/)。每次保留 prompt、CLI 日志、根/子 JSONL、工具调用、插件返回、usage、时间与清理信息。`review.json` 为 15 项人工审阅，`summary.json` 为汇总，`aggregate.json` 为三组统计；`profile-before.json` / `profile-after.json` 只保存抽查哈希与大小。部分 CLI 原始证据另外在该目录各组 `evidence/` 或日志记载的 runtime 路径下。目录被 Git 忽略，已检查已知密钥脱敏，不提交 Profile、Cookie 或运行日志。

以下是当次使用的命令。复现相同三工具协议需对应冻结包与当时 runner；当前源码已改为单工具，运行这些参数会测试当前接口，不能冒充历史构建复现。会产生真实 API 请求，不应覆盖已有记录：

```bash
python3 scripts/evaluate-shopping.py --compare --chrome-profile Default --output runtime/subagent-evaluation/new-comparison
python3 scripts/summarize-shopping-evaluation.py runtime/subagent-evaluation/new-comparison
```

Runner 核对 Node / pnpm 版本、去除代理、建立三种 DSH profile，再用 `scripts/run-dsh.sh` 启动固定 CLI。每个用例结束后才收集结果，无中途干预、无外层超时。汇总脚本不自动判语义成功，新的运行仍需人工审阅。该脚本依赖本机已配置的 headless profile 和凭据，不是新安装产品功能承诺。

核心实现此前 `pnpm check` 的 69 项测试、类型检查及构建通过；证据校验末次小调整通过相关 15 项测试、类型检查与构建，见第一轮记录。本轮冻结核心，只新增评估脚本与文档；两个 Python 脚本语法检查、15 次真实执行、汇总及 `git diff --check` 通过，未重复声称干净 Profile 安装验收。
