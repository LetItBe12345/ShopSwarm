# ShopSwarm 设计说明

## 定位

ShopSwarm 是 DSH 的外部插件，不是独立 Agent，也不负责 Subagent 调度。DSH 负责加载插件和运行 Agent；Skill 告诉 Agent 什么时候使用工具以及失败后如何 fallback。

## 最小调用链

```text
用户任务
  -> DSH Lead Agent
  -> 可选的多个 Subagent
  -> shopswarm_research
  -> Jev 选择页面动作
  -> ShopSwarm 校验动作
  -> agent-browser 操作 Chrome
  -> 页面结果和报价证据
  -> Agent 汇总并回复用户

Jev 超时或返回无效动作时，当前来源 Subagent 读取结构化 `handoff`，改用 `shopswarm_browse` 继续操作。只有 Subagent 判断来源需要人工处理、无法继续或需要换来源时，才把来源交回 Lead；Lead 不直接点击页面。
```

## 三个工具

`shopswarm_research` 是主工具。它负责一次来源研究：打开页面、读取快照、让 Jev 选择动作、执行动作、提取报价、检查证据，并在需要时重新打开页面核对。

`shopswarm_browse` 是明确步骤工具。调用方直接提供动作，插件不做自动决策，也不调用 Jev。它主要用于 Agent 已经知道页面步骤时的快速操作。

`shopswarm_diagnose` 是诊断工具。它检查运行环境和浏览器连通性，不做购物研究。

## Jev 的位置

Jev 只做页面动作选择，不调用浏览器、不提取最终报价、不做价格计算。具体点击由 ShopSwarm 的执行代码发出，底层由 agent-browser 执行。

如果 DSH Agent 已经能直接使用浏览器工具，Jev 不是强制路径；Skill 应优先使用最简单的可用路径。ShopSwarm 的价值是统一工具入口、隔离浏览器、校验目标和保留结果。`shopswarm_browse` 是当前来源 Subagent 在 Jev 失败后的直接操作入口。

## 结果处理

模型说完成不等于任务成功。成功需要页面证据支持任务要求。缺少证据、登录、验证码、频控和页面失效都作为结果返回。Jev 或浏览器动作失败时，`handoff.owner=subagent` 要求当前来源 Subagent 用 `shopswarm_browse` 继续；`handoff.owner=lead` 才允许 Lead 重新分派、换来源或结束该来源。

## 收尾范围

当前目标只有：能被 DSH 安装和加载，Agent 能用它完成通用购物研究。暂不做性能评估、Token 统计、公平比较、专用品类模型、价格监控、自动购买或支付。
