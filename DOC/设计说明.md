# ShopSwarm 设计说明

## 定位

ShopSwarm 是 DSH 的外部插件，不是独立 Agent，也不负责 Subagent 调度。DSH 负责加载插件和运行 Agent。每个来源由当前来源 Subagent 负责，Jev 是该来源浏览器动作的默认选择器。

## 一个来源任务的执行流程

```text
DSH Lead Agent
  -> 当前来源 Subagent
  -> shopswarm_research 开始来源任务
  -> 创建并持有一个后台浏览器会话
  -> Jev 选择动作
  -> ShopSwarm 校验动作和页面版本
  -> agent-browser 在同一会话执行动作
  -> 读取新快照并继续 Jev 循环

Jev 决策失败或页面反复无进展
  -> 暂停来源任务并返回 continuationId
  -> 当前来源 Subagent 用 shopswarm_browse 在同一会话恢复页面
  -> shopswarm_research 用 continuationId 恢复 Jev

Jev 判定完成
  -> 提取报价
  -> 在同一浏览器会话重新打开商品页并核验
  -> 关闭会话并返回结果
```

Jev 超时、返回无效动作、没有可用动作或反复无法推动页面时，当前来源 Subagent 临时接管。浏览器传输错误不触发 Subagent fallback；登录、验证码、频控和无法核验的结果交回 Lead。

## 工具

`shopswarm_research` 开始或恢复一个来源任务。开始时传入来源 URL、研究目标、商品型号、规格和可选卖家。Jev 默认选择页面动作；工具校验目标、调用 agent-browser 执行动作、提取报价，并在同一会话重新打开商品页核验。

当 Jev 无法继续时，工具返回绑定当前 Subagent 的 `continuationId`。恢复调用只传这个 ID，不重新创建来源任务。

`shopswarm_browse` 只用于 Jev 暂停后的短时恢复。它必须接收 `shopswarm_research` 返回的 `continuationId`，并在该来源当前页面和浏览器会话中执行明确动作。动作批次没有固定的 8 步限制；单个浏览器命令仍受超时配置限制。页面恢复后，Subagent 应尽快调用 `shopswarm_research` 并传回同一 ID，让 Jev 继续研究。

`shopswarm_diagnose` 检查运行环境和浏览器连通性，不做购物研究。

## 浏览器会话和恢复句柄

一个来源研究从开始到结束持有一个后台浏览器会话。Jev、Subagent fallback 和报价复核共用该会话。插件在进程内保存浏览器对象、socket 目录、当前页面版本、任务上下文和动作历史；仅向当前来源 Subagent 返回不透明的 `continuationId`，并校验 DSH Agent 身份。

Subagent 接管期间，该来源仍占用一个浏览器资源名额。默认 5 分钟没有后续调用时，插件关闭会话并释放名额；研究结束、取消或插件卸载时也会清理会话。过期句柄不能重新打开已关闭的会话。

## Jev 和动作执行

Jev 只从当前页面有效动作集合中选择下一步，不直接操作浏览器、不提取最终报价、不计算价格。ShopSwarm 重新读取页面并校验目标后，由 agent-browser 在该来源会话中执行动作。Subagent fallback 也使用同一执行适配层和最新快照。

Jev 的 `DONE` 不代表任务成功。报价必须包含商品身份、规格、卖家、价格和来源页面证据；插件会在同一浏览器会话重新打开商品页后复核。登录、验证码、频控和证据不足不能伪装为成功。

## 收尾范围

当前目标是让插件可被 DSH 安装和加载，并完成只读购物研究。暂不做性能评估、Token 统计、公平比较、专用品类模型、价格监控、自动购买或支付。
