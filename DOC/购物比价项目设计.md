4. DSH 多 Agent 怎么和 Browser 对应

这一层实际上非常漂亮。

DSH 本身已经有 Agent 生命周期：

agent/created
agent/disposed

现有代码也大量使用这两个事件做 per-Agent resource 管理。

所以你的 Plugin 可以维护：

TypeScript
Map<Agent, FastBrowserSession>

大概：

DSH Lead Agent
│
├── Tmall Subagent
│      └── BrowserSession A
│
├── JD Subagent
│      └── BrowserSession B
│
├── Taobao Subagent
│      └── BrowserSession C
│
└── Official-site Subagent
       └── BrowserSession D

agent/disposed：

→ browser.close()
→ kill worker
→ clean temp profile

这完全符合 DSH 自己现有 Browser provider 的设计思想：浏览器资源属于具体 live Agent / Session，而不是全局共用。它自己的 Stagehand provider 也是类似的 per-session resource 模型。

所以你不用改 DSH。
