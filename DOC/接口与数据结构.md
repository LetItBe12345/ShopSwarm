# 接口与数据结构

日期：2026-09-23。状态：M1.3 最小购物报价载体；后续任务可按已验证需求扩展。

## M1.3 报价类型

实现位于 `src/types.ts`。`ProductIdentity` 记录型号字符串和已观察到的名称/取值规格；它不负责判断两个商品是否同款。`Offer` 表示一个已知卖家的单条报价，包含币种、标价、已观察到的费用、商品页地址、采集时间和字段证据。没有观察到卖家时不创建报价。

标价和费用使用 `KnownOrUnknown<Money>`。已知金额以币种的整数最小单位记录，例如人民币分；未知金额必须显式写成 `unknown`，不能以 `0` 代替。费用数组为空表示尚未观察到费用，不表示已确认没有费用。已知金额的币种必须与报价币种一致。

`Evidence` 当前只保存字段名、页面 URL、观察时间和非空页面文本摘录。M1.3 不要求每个已知字段都有证据；证据与字段的完整对应、截图和持久化留到后续任务。

`validateOffer(input: unknown)` 执行运行时结构校验，并在错误中指出字段路径。它检查字符串非空、三位大写币种代码形状、安全整数金额、金额币种一致、费用种类不重复及证据字段合法；不校验 ISO 4217 币种表，不判断商品匹配、价格条件或报价真实性。

## 浏览器基线测试

M1.3 的五个静态页面分别覆盖搜索、规格选择、延迟加载、遮挡和失效元素。测试在本机 `127.0.0.1` 的临时端口提供页面，不从页面抽取报价。阶段耗时只记录在测试结果中，不属于浏览器适配层返回值，也不设置性能阈值。

## M2.1 动作选择接口

实现位于 `src/jev.ts` 和 `src/text-input.ts`。`ShoppingTaskContext` 由目标、约束、完成条件、已确认进度和可选的明确输入文本组成。调用方把当前 `BrowserPageState` 和近期动作结果交给 `buildActionRequest`，它截断过长的任务字段及页面快照，只把最近 8 条动作放入本次 Jev `state`。Jev 不保存跨调用状态；页面文本是观察数据，不能改写任务目标。当前默认中转站、模型及密钥变量见 [Jev 中转站使用](Jev中转站使用.md)。

候选目标只来自本次快照的前 100 个元素引用。`CLICK`、`TYPE_TEXT` 按元素角色生成候选；`SELECT` 只在下拉框的选项可从当前快照读到时生成，值使用快照中的可见选项文字。其余可选操作是滚动、返回、`DONE` 和 `BLOCKED`。当前浏览器适配层没有无条件等待操作，因此不向 Jev 提供 `WAIT`。目标只有一个时在本地确定；有多个时与操作问题一起交给 Jev。返回的操作和目标必须属于这次请求的候选集合。执行入口在 Jev 返回后重新读取快照，核对浏览器会话、页面版本、目标和下拉选项；发生变化时拒绝动作。`DONE` 仅是待核对的模型判断，独立完成检查属于 M2.2。

`TYPE_TEXT` 先按元素引用或可访问名称从 `textInputs` 取明确文本；缺少或为空时才用 `DEEPSEEK_API_KEY` 调用 `deepseek-flash`。文本模型可以返回 `{"text":null}`，此时不填写。调用结果分别记录来源、模型、耗时、输入及输出 Token。DeepSeek 的聊天响应不返回实际扣费金额，`costUsd: null` 表示费用未知；直接复用任务文本时费用为 0。

页面快照可能包含登录后的地址、手机号等信息。根据 M2.1 已确认选择，首版不因这类页面内容停止 Jev 调用；Cookie 和密钥不进入 `state`。本接口目前不构成完整购物动作循环，也不进行报价提取或完成判定。

## M2.2 单站研究与完成检查

实现位于 `src/shopping/`，DSH 工具名为 `shopswarm_research`。输入是单站起点 URL、目标、明确型号、规格对象数组及可选卖家。DSH Agent 负责从用户任务形成这些条件；ShopSwarm 不让页面文本改写条件。工具一次调用拥有一个动作会话，选出 `DONE` 后再新建独立会话重开商品 URL。两个会话在调用结束或取消后关闭。动作会话使用 Chrome `Default` Profile 的临时副本，不连接用户正在使用的窗口。

Jev 的 `DONE` 只触发检查。DeepSeek `deepseek-flash` 从完整页面快照提出字段和原文摘录；`checkObservedOffer` 要求摘录实际出现在页面中，型号和任务指定规格匹配，规格证据显示当前选中，卖家有证据，标价有币种和可解析金额。金额按整数分记录。运费、税费、优惠为未知。第一次检查失败时，把缺项传回 Jev；同一页面、同样缺项再次 `DONE` 时返回 `no_progress`。页面内容变化后重验，不沿用旧证据。

首次检查通过后，新会话打开候选 URL。原生下拉框能识别目标选项时重新选择规格，再取得完整快照，重新抽取并检查。重开后的型号、规格、卖家和币种须与首次一致；价格变化时采用重开后观察到的标价和采集时间。无法重现时返回 `verification_failed`，候选报价只放在 `candidate`，不放在已验证 `offer`。该检查证明页面报价可重现，不保证结算价或库存持续有效。

结果包含 `status`（`success`、`blocked`、`failed`、`cancelled`）、`reasonCode`、原因文本、已核实 `progress`、`missing`、页面 URL/摘录、可选 `offer` 或 `candidate`、调用次数与耗时指标。`login_required` 带 `userMessage`，DSH 应让用户在原 Chrome Profile 重新登录；用户回复已登录后用原任务条件新建会话，不轮询登录态。`captcha` 只返回阻塞，不自动破解。单条浏览器命令超时分类为 `browser_timeout`。多站并发与结果汇总属于 M3。
