# ShopSwarm 收尾实施计划

更新日期：2026-09-23。

这份文档替代旧的 roadmap、M4/M5/Q TODO 和 Coding Plan 专用规划。目标不是继续扩展项目，而是用最小改动把 ShopSwarm 收尾成一个能在 DSH 中实际使用的浏览器研究插件。

## 1. 最终目标

最终使用方式保持一条链路：

`用户任务 -> DSH Lead Agent -> 多个 DSH Subagent 并行 -> ShopSwarm 工具 -> 浏览器/Jev -> Subagent 返回 -> Lead Agent 生成报告`

项目不再承担以下职责：

- 不自己实现 Agent 调度器；
- 不自己实现跨来源任务编排框架；
- 不为 Coding Plan、商城、API 套餐分别建立领域模型；
- 不建立 provider benchmark、评分体系、性能排行榜；
- 不要求所有来源先被归一化成统一 schema 才能由 Agent 总结；
- 不把报告格式硬编码到 TypeScript。

DSH 和模型本身已经具备任务拆分、并行、判断、归纳和写报告的能力。ShopSwarm 只补浏览器执行和快速动作决策这一块。

## 2. 最终架构

### 2.1 DSH Lead Agent

Lead Agent 是总调度者。

职责：

- 理解用户任务；
- 决定需要调查哪些来源；
- 为独立来源派出多个 Subagent；
- 把共同目标和每个来源分别交给对应 Subagent；
- 收集各 Subagent 的事实、证据、unknown 和失败原因；
- 根据用户问题生成最终报告。

不要在 ShopSwarm 内重复实现这一层。

### 2.2 DSH Subagent

一个 Subagent 对应一个来源或一个独立子问题。

Subagent 决定：

- 当前来源要找哪些信息；
- 是否继续浏览；
- 是否换页面；
- Jev 卡住后下一步怎么做；
- 什么信息已经足够；
- 当前来源最终如何回传。

ShopSwarm 工具不应该替 Subagent 定义一个复杂的领域完成协议。

### 2.3 ShopSwarm Plugin

Plugin 保留最小浏览器能力：

- 打开页面；
- 获取快照；
- 执行浏览器动作；
- 调用 Jev 从当前 Action Space 里选动作；
- 返回页面状态、证据、阻塞和必要的恢复信息；
- 管理本工具创建的浏览器资源。

Plugin 不负责：

- 多 Agent 调度；
- 最终报告；
- provider 排名；
- Coding Plan 专用归一化；
- 统一的 comparability engine；
- benchmark。

### 2.4 agent-browser

agent-browser 继续作为实际执行层。

当前已经完成的 session、snapshot、click、fill、select、scroll、back、cleanup 等能力继续复用，不重新封装第二套浏览器运行时。

### 2.5 Jev

Jev 是“快速动作选择器”。

它的优势是便宜、快，并且可以被限制在当前页面的合法 Action Space 中。因此正常路径继续让 Jev 先选动作。

但是 Jev 不是最终 Agent。Jev 失败不应该直接等价为来源任务失败。

## 3. Jev -> DSH Subagent fallback

这是收尾阶段唯一值得补的核心行为。

### 3.1 当前问题

当前 `src/shopping/run.ts` 在这些情况会直接结束工具调用：

- `chooseAction` 抛错 -> `jev_error`；
- Jev 返回 `BLOCKED` -> `no_progress`；
- 相同页面重复 `DONE` 且缺项不变 -> `no_progress`；
- 相同动作连续无页面变化 -> `no_progress`；
- 某些动作执行失败 -> 直接返回 browser error。

这样会把“Jev 这一步没处理好”和“这个来源真的无法继续”混为一谈。

### 3.2 目标行为

区分两类结束：

**真实外部阻塞**

例如：

- login required；
- captcha；
- site rate limited；
- 页面无法访问；
- 浏览器进程失败；
- 用户取消。

这些可以直接返回 blocked / failed / cancelled。

**需要 Agent 接管**

例如：

- Jev 请求失败；
- Jev 返回 BLOCKED，但页面本身仍可观察；
- Jev 重复无进展；
- 当前页面需要比 Jev 更强的语义判断；
- 目标选择失败但页面仍然存在。

这些不应被定义成最终失败。工具返回一个明确的 handoff 结果，把控制权交还当前 DSH Subagent。

### 3.3 最小实现

不要让 Plugin 在内部再 spawn 一个 Agent。

调用 `shopswarm_research` 的当前 DSH Subagent 本身就是 fallback owner。

下一次代码修改只需要让工具返回足够的 handoff 信息，例如：

- status: `needs_agent` 或继续使用 `blocked` 但增加明确 reasonCode；
- 当前 URL；
- 当前页面摘录；
- 当前 progress；
- 当前 missing；
- Jev 最近动作与失败原因；
- 当前可执行动作的概要。

Skill 告诉 Subagent：收到 handoff 后，由它自己判断下一步，并使用现有 `shopswarm_browse` 或重新调用研究工具继续。

首版不为了“无缝接管同一个浏览器进程”引入跨工具调用 session manager。重新观察当前 URL 足够完成大多数任务。只有真实使用证明状态丢失是主要问题，再增加 resume handle。

这比在 Plugin 内嵌套第二个 Agent 简单得多。

## 4. Skill 设计

优先只保留一个 `shopping-research` Skill。

这个 Skill 同时描述：

- Lead Agent 如何拆来源；
- Subagent 如何研究单来源；
- Jev 失败后如何由 Subagent 接管；
- Subagent 如何回传；
- Lead Agent 如何写报告。

不要现在就拆两层 Skill。只有后续发现文件太长、Lead 和 Worker 指令明显互相干扰，再拆成：

- `shopping-research`：Lead 编排和报告；
- `source-research`：单来源浏览和 fallback。

“Skill 包 Skill”可以作为组织方式，但不是当前完成条件。

## 5. 报告策略

最终报告交给 Lead Agent，而不是 TypeScript comparator。

Subagent 返回事实和证据。Lead Agent 根据用户任务决定如何比较。

最低要求只有：

- 不编造没找到的信息；
- unknown 明确保留；
- 事实能对应来源；
- 一个来源失败不能伪装成已经覆盖；
- 用户要求比较时，说明比较采用的口径。

不再要求：

- `PlanOffer`；
- requiredFields / desiredFields 领域协议；
- priceType / quota / billing 的统一类型系统；
- comparability engine；
- 固定排序器；
- golden report；
- provider score。

这些规则如果某个任务真的需要，写进对应 Skill 或用户任务即可。

## 6. Coding Plan 的定位

Coding Plan、LLM API 套餐和 GLM-5.3 继续保留为测试用例，因为它们适合验证：

- 页面结构不同；
- 来源不同；
- 价格信息存在条件差异；
- unknown 很常见；
- 可以测试多个 Subagent 并行。

但它们不再定义 ShopSwarm 的产品数据模型。

测试用例应该服务架构，而不是反过来让架构服务测试用例。

## 8. 下一次代码 PR

这次 PR 不新增实现代码。下一次只做一个很小的 Fix PR。

目标：**Jev 失败后把控制权明确交回当前 DSH Subagent。**

建议修改位置：

### `src/shopping/run.ts`

- 把 `jev_error`、Jev `BLOCKED`、重复 no-progress 从“最终失败”改成“Agent handoff”；
- 返回当前 URL、pageExcerpt、progress、missing 和近期动作；
- 保留 login/captcha/rate-limit/cancelled 等真实 blocker；
- 不新增领域模型；
- 不新增 benchmark。

### `src/index.ts`

- 只扩展 `shopswarm_research` 的返回 schema，使 handoff 状态能被 DSH Agent 看懂；
- 不新增一组复杂工具；
- 如果现有 `shopswarm_browse` 足够，就直接复用。

### `skills/shopping-research/SKILL.md`

- 明确 Subagent 收到 handoff 后接管；
- 给出简单恢复顺序：重新观察 -> 判断下一步 -> 必要时手工 browse -> 继续或结束来源；
- Lead Agent 最后直接写报告。

### 测试

只补能证明 fallback 生效的测试：

1. Jev 抛错时返回 handoff，而不是终止来源；
2. Jev BLOCKED 时返回 handoff；
3. login/captcha 仍然是 blocker；
4. 取消和 cleanup 行为不回归。

不做模型质量评分，也不做 benchmark。

## 9. 完成标准

ShopSwarm 可以收尾时，只需要满足：

- 能作为 DSH 外部 Plugin 安装；
- DSH Agent 能调用浏览器工具；
- 多个 DSH Subagent 可以并行研究多个来源；
- Jev 正常时能辅助推进页面；
- Jev 失败时 DSH Subagent 能接管；
- 单来源结果能带回事实、证据、unknown 和 blocker；
- Lead Agent 可以根据 Skill 生成最终报告；
- `pnpm check` 通过；
- 文档不再暗示还存在 M4/M5/Q 大型路线。

达到这些条件就停止扩展。后续新需求按真实使用问题单独修，不再提前建设平台化能力。
