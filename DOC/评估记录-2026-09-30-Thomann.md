# Thomann 第一轮真实端到端评估

日期：2026-09-30。实现依据：已合并的 `main` / `origin/main`，提交 `c4b1661`。记录分支：`eval/thomann-first-round`。

## 方法和边界

来源：https://www.thomann.de/de/shure_sm_7b_studiomikro.htm 。任务是确认 Shure SM7B 单只新品的身份、报价、币种、含税条件、库存与德国配送条件。

两个方案各运行一次，使用同一个 prompt、新 DSH 会话和独立后台浏览器，不连接用户 Profile。通过 `bash scripts/run-dsh.sh --profile headless --json <prompt>` 启动；基线额外加载仅禁用 ShopSwarm 的 patch。模型自行选择工具、恢复和兜底；启动后没有追加提示、强制停止或人工浏览器操作。两个方案均允许主 Agent 使用现有工具完成任务。

环境：Node 24.21.0、pnpm 11.7.0、DSH 0.1.7-alpha.2、agent-browser 0.38.1、ShopSwarm 0.2.0。实际 DSH 模型标识为 `deepseek-official/deepseek-flash`，固定版本的目录名称为 DeepSeek-V41-Flash，不能把计划里的“V4 Flash”当成已核实的精确模型版本。DSH 与浏览器移除代理变量；浏览器使用 `--headed false --auto-connect false`。

更正：后续重跑发现旧 host 工具硬编码 `profileName: 'Default'`。该版本 agent-browser 会只读复制用户 Chrome Default 登录态，因此本记录先前关于“插件方案不读取用户 Profile”的说明不成立，不能将该组列为完全满足会话隔离协议。没有当时原 Profile 的前后完整校验数据，不能宣称其未被修改。后续修复已移除默认 Profile 并隔离配置，验证结果另行记录。

两个方案均遇到 DSH bash 沙箱中的 socket 目录权限及跨命令 daemon 生命周期问题；这些耗时属于执行环境，不能全部归因于网站或 Jev。浏览器在后台运行，2 秒间隔的焦点采样未观察到变化；结束时默认会话列表为空，进程检查未发现遗留浏览器。采样不能证明每一瞬间的焦点状态。

## 已确认问题

1. **欧元报价不能通过校验。** `src/shopping/verify.ts` 的 `priceFromExcerpt` 只支持人民币、美元及前置币种。`398 €` 和德国小数格式均不支持。第二次来源研究传入空规格后，仍只缺价格/币种证据。这是代码能力缺口，不是缺 API Key，也不是 Jev 多点击几次能解决的问题。
2. **暂停会话导致新任务等待。** `src/index.ts` 默认只有一个浏览器任务名额。暂停的 continuation 保留该名额，工具没有暴露主动结束/替换来源的操作。主 Agent 新开研究时等待旧来源 5 分钟闲置过期，对应一次 research 调用耗时 305.745 秒。应提供明确的结束/替换方式，或快速返回可执行的资源冲突说明。
3. **商品条件和控件选择混用。** Agent 首次把类型、全新状态和排除项全部传入 specs，而 `selectedSpec` 要求 selected/checked 等选择状态。静态属性与排除条件不属于控件选择。应区分身份条件、排除条件与可选变体，并对不同条件使用相应页面证据。
4. **重复 DONE 没有解决确定性的校验失败。** 两个来源合计 10 次 Jev 决策、10 次字段提取。校验器拒绝价格后，系统仍重复请求模型；这种失败应该反馈为解析/证据问题，避免交给动作模型不断尝试页面恢复。
5. **Token 记录不完整。** `SelectedAction.usage` 有返回，但研究指标没有累计 Jev 用量。无法给出完整系统 Token 或费用结论。

累计指标按每个 continuation 的最后一份累积结果计算，不能把恢复前后的指标重复相加：Jev 决策耗时 10.673 秒，提取耗时 17.158 秒；提取输入 60,679、输出 2,640 Token。主 DSH 观测用量：基线 1,923,931，ShopSwarm 1,377,564（均包含缓存读取 Token）。ShopSwarm 加提取后的已知小计为 1,440,883，另有未知 Jev 用量。这些数字不是费用，也不能据此宣称节省完整任务 Token。

## 判断与建议（尚未实施）

通用购物研究仍可实现。当前版本没有证明 Jev 能加速；本轮插件路径的可用性下降，但主要阻断来自校验和资源管理，不能推导出 Jev 模型本身更差。去掉这次五分钟等待后的时间也不能当成下一版本实测成绩。

值得继续做一轮小范围修复：欧元与德国价格格式、明确的来源结束/替换、条件类型和失败分类。不要先增加站点、浏览器池或更复杂的 Agent 调度。

Jev 的保留价值应通过修复后的实验决定：只读且报价已可提取的页面不必强制经过动作决策；需要选择规格、导航和表单操作时再使用 Jev。证据校验仍应保留。可与直接浏览器路径比较完成情况及耗时，记录 Jev 全量用量；若多次真实任务仍没有减少操作或改善成功率，将 Jev 降为可选路径更合理。

本轮仅一站、每个方案一次，不是成功率或总体速度结论，也没有证明未来改动会通过。建议先修复已确认阻断，再决定是否继续完整 30 次评估。
