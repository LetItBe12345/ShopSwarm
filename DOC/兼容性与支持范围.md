### DSH 外部集成

DSH 支持树外 Bundle。Bundle 在 `package.json` 的 `dsh.bundle.patch` 中声明 patch，使用 `dsh plugin --profile <name> add <package>` 安装到 profile。Profile 从自己的 `node_modules` 解析树外 Bundle。ShopSwarm 因此继续采用外部 Bundle、Host Plugin 和 Skill，不修改 DSH 源码。

### 工具参数与返回值

工具使用 `defineTool(...)` 构造定义，并通过 `ctx.tools.register(...)` 注册。参数在 `parameters` 中用 DSH 支持的 JSON Schema 描述。工具定义必须包含：

- `output.schema`：成功值的 JSON Schema。
- `output.render(args, value)`：把结构化成功值投影成模型可见的 `ContentBlock[]`。
- `execute(args, exec)`：返回满足 `output.schema` 的、可无损 JSON 序列化的值。

DSH 运行时把执行结果归一为 `ToolExecutionResult`：成功结果含 `isError: false`、结构化 `value` 和模型可见 `content`；失败结果含 `isError: true`、`error` 和 `content`。ShopSwarm 工具体不应自行伪造这一外层结果，也不能直接返回任意文本代替声明的结构化值。

源码依据：

- [ToolDefinition 与 output](https://github.com/deepseek-ai/deepseek-harness/blob/00102833dfaee1da9f48a3a8eae9d34005a75218/packages/core/tools/src/index.ts#L212-L236)
- [ToolExecutionResult](https://github.com/deepseek-ai/deepseek-harness/blob/00102833dfaee1da9f48a3a8eae9d34005a75218/packages/core/tools/src/index.ts#L572-L598)
- [工具注册与返回的 disposer](https://github.com/deepseek-ai/deepseek-harness/blob/00102833dfaee1da9f48a3a8eae9d34005a75218/packages/core/tools/src/index.ts#L1056-L1086)

M0.2 的诊断工具只验证这套最小接口。购物工具的 `Task`、`Offer` 和 `Evidence` 字段在 M1/M2 定义，M0.1 不提前固定尚未验证的业务契约。

### Agent 身份与调用归属

执行上下文提供：

- `exec.agent?: Agent`：由 Agent loop 设置，工具不得从模型参数接收或信任 Agent 身份。
- `exec.agent.id`：基于 Session 的 Agent 身份，类型为 `SessionId`。
- `exec.callId`：当前工具调用身份。
- `exec.rootCallId`：根工具调用身份，嵌套调用时用于关联整棵调用树。

ShopSwarm 遇到 `exec.agent === undefined` 时应返回明确错误，不创建浏览器。浏览器会话至少以 `exec.agent.id + exec.callId` 关联，不能只用站点名或模型提供的字符串作为资源归属。

源码依据：

- [ToolExecutionInput](https://github.com/deepseek-ai/deepseek-harness/blob/00102833dfaee1da9f48a3a8eae9d34005a75218/packages/core/tools/src/index.ts#L321-L351)
- [Agent.id](https://github.com/deepseek-ai/deepseek-harness/blob/00102833dfaee1da9f48a3a8eae9d34005a75218/packages/core/agent/src/types.ts#L14-L18)

### 取消

`exec.signal` 是必传的 `AbortSignal`。异步工具必须观察它，或把它传给下游操作。DSH 在工具体开始前取消时返回 `ABORTED_BEFORE_DISPATCH`；工具体开始后取消时返回 `ABORTED`。DSH 不会丢下已经启动的 Promise，它会等待工具拥有的工作停止。因此 ShopSwarm 必须把取消继续传给子进程等待、Jev HTTP 请求和浏览器动作，并让清理流程最终结束。

### 释放

`ctx.tools.register(...)` 本身是 Cordis effect，插件卸载时会自动撤销注册。浏览器进程、临时目录、定时器和连接等外部资源不由工具注册管理，必须由插件另行负责：

1. 每次工具调用使用 `try/finally` 关闭本调用创建的资源。
2. 插件维护仍存活资源的归属表，并用一个 `ctx.effect()` disposer 作为卸载兜底。
3. disposer 只关闭 ShopSwarm 创建且仍归属于该插件实例的资源。
4. 有顺序要求的异步清理放在同一个 disposer 内依次 `await`；Cordis 可能并发执行多个异步 disposer。

源码依据：[Cordis 生命周期与 effects](https://github.com/deepseek-ai/deepseek-harness/blob/00102833dfaee1da9f48a3a8eae9d34005a75218/docs/cordis-tutorial/02-lifecycle-and-effects.md#L5-L65)。

### 执行中发现并修复的问题

1. DSH profile 默认拒绝 agent-browser 安装脚本。验收流程改为先初始化 profile，再在其 `pnpm-workspace.yaml` 中明确允许 `agent-browser`，随后安装 tarball。
2. DSH 禁止从 `.env` 设置 `DEEPSEEK_BASE_URL`。本地 `.env` 只保存 API Key，官方地址使用 DSH 默认值。
3. DSH 收到 SIGINT 后最多等待 5 秒便强制退出，而 agent-browser 默认操作可能持续更久。ShopSwarm 现在使用独立 socket 目录、较短的一次性诊断超时和会话专属清理看门进程。看门进程只处理本任务派生的 PID，不会关闭其他会话。

M0 阶段只证明外部扩展、真实 Agent 工具调用和资源释放链路可工作。真实购物站点、登录 Profile、Jev 动作循环和并行研究仍未验证。

## M3.1 DSH 分发与浏览器资源限制

2026-09-23 核对 DeepSeek Harness 本地参考副本（[上游仓库](https://github.com/deepseek-ai/deepseek-harness.git)，提交 `00102833dfaee1da9f48a3a8eae9d34005a75218`）的 `docs/subsystems/subagent.md`、`packages/subagent/tool-subagent/README.md` 和 base Bundle 配置。当前安装的 DSH `0.1.7-alpha.2` 已提供 `subagent` 的 `spawn` 后端。一次性 `headless` 回合使用 `run_in_background: false` 才能在进程结束前取得子任务结果；默认后台模式只返回子 Agent ID。本项目没有另写调度器。

ShopSwarm `maxConcurrentBrowserTasks` 默认 2，限制单个 DSH Host 进程同时进入的浏览器工具调用。它覆盖 `shopswarm_diagnose(checkBrowser=true)`、`shopswarm_browse`、`shopswarm_research`；等待按 FIFO，取消等待不占槽位，工具清理结束后释放。`shopswarm_research` 重开复核时可能同时拥有两个浏览器会话，所以此值不是进程级浏览器会话数的精确上限；多个独立 DSH 进程也不共享此限制。Node.js 24.21.0 下类型检查、构建和 56 项测试通过，详见 [M3.1 执行记录](../TODO/done/M3.1-接入 DSH 任务分发与资源限制.md)。

真实 DSH Lead 在独立 `headless` profile 中分别顺序、并行分发 GLM-5.3 任务给 [智谱 Coding Plan](https://docs.bigmodel.cn/cn/coding-plan/overview) 和 [星模 XModel 按量 API](https://www.modelxing.com/zh/models/glm-5-3)。两个页面可由独立 headless 浏览器读取，但四次 `shopswarm_research` 均返回 `blocked/no_progress`，未取得完整可复核报价。顺序运行的缺项分别是明确标价/币种证据、当前验证器要求的型号证据。此记录只验证分发、等待和结构化失败，不构成这两个来源的价格支持承诺。OpenRouter 和 B.AI 页面本次直接浏览超时，未列为可访问来源。
