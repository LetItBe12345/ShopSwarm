## 判定方式

核心是实际回答用户标价问题：商品、要求配置、一次性购买报价、币种、价格条件、真实来源和采集时间。完整结果记为通过；有部分证据但核心不足记为部分完成；无报价或运行未能形成有效答案记为未通过。进程退出、模型自称成功、Jev DONE 都不直接计为通过。

多个符合要求的配置可以分别列价并注明剩余选项，不能任取一个当唯一价格。Thomann 用例明确允许新品或单只证据缺失时说明未知；未要求的税费、库存、运费保持 unknown，不自动判失败。将未知宣称已证实是答案质量问题，须单列。

Jev 请求数、返回决策、浏览器动作尝试与实际成功、CLI fallback 分开核对。浏览器 metrics.browserActions 含初始导航，不能把它全部算成 Jev 动作。一次 Jev 调用或 DONE/MORE_TARGETS 不等于实际动作贡献。两组对照判断整个方案差异；没有额外 Jev 消融组，不能证明差异单独由 Jev 引起。

单轮、同一机器和工作区，无法消除站点状态、模型随机性、服务等待和缓存影响。要求不读取历史评估文件，但并非不可访问的盲测隔离。因此不宣称统计显著或稳定提速，也不宣称全部德国购物网站可用。

## Jev 实际发生了什么

| 插件用例 | 请求数 | 非初始导航的浏览器动作尝试 | 实际结果 |
| --- | ---: | ---: | --- |
| Aeron | 0 | 0 | act 导航/就绪检查超时，请求前返回；同会话 CLI 恢复并核对配置 |
| iPhone | 3 | 1 | 首次 act 两步后 MORE_TARGETS，后续 act 一步仍 MORE_TARGETS；256GB尚未选中，CLI显式点击后完成 |
| Thomann | 1 | 0 | MORE_TARGETS；随后 read 取得报价，DSH余额中断 |
| BIKE24、Samsung | 未进入调用 | 未进入调用 | 主模型第一步402，不能评价 Jev |

合计4次真实 Jev请求，模型决策等待4012ms，输入14887、输出1923 Token。browserActions累计包含每个会话一次初始导航，汇总已扣除，不能把三个导航算为 Jev 动作。iPhone第一次 act 的 steps=2、累计 browserActions=2，最终为 MORE_TARGETS；按当前循环只有先前动作成功且返回 agent_review 才会继续，支持一次成功原生动作。多步工具只返回最后决策，没有逐步名称/目标，无法确认那一步操作了哪个控件，更不能证明帮到了容量选择。

可确认：当前版本确实调用了 Jev，Jev 请求可用，也有一次原生动作执行。尚未证明：它完成关键配置、减少 DSH 推理或稳定提速。iPhone实际容量选择仍由CLI完成；Aeron成功不依赖Jev。

### 可定位的上下文问题

当前源码每批默认40个动作候选，页面文本默认6000字节原文切片。iPhone 的 MORE_TARGETS 返回 nextTargetOffset=40；来源 Agent 第二次 act 没有传 targetOffset 或 pageOffset，又从首批/首段开始。action=read 只是向来源 Agent 读更多快照，不会自动更新下一次 Jev 上下文。Thomann 也通过 read 得到价格，但 Jev 首批仍返回 MORE_TARGETS。

因此目前瓶颈不只是“100个还是40个”：候选分页、文本分页的接续职责容易遗漏，具体配置控件可能不在当前上下文中。Jev收到“读取商品与价格”的语义目标也超过纯动作选择职责。优先建议让adapter明确管理MORE_TARGETS的接续，并按动作子目标给上下文，保留逐步决策和执行记录；这些是后续设计建议，本轮没有修改产品代码，也未验证该建议带来的收益。
