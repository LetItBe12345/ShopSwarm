# 价格研究调用流程复盘

记录日期：2026-09-24  
来源：一次 GLM Coding Plan 价格研究任务的调用记录和事后复盘

这份记录描述调用流程问题。它和 `001-dsh-web-runtime-errors.md` 中的网络、工具错误分开处理。

## 1. Jev 输入页面和目标过宽

三次研究调用分别使用了错误或不合适的页面形态：

- `bigmodel.cn/claude-code` 是猜测的 URL，实际发生了跳转；目标要求读取多个套餐和周期。
- `z.ai/subscribe` 是重型 SPA，页面需要等待客户端渲染，目标没有给出明确控件或文本锚点。
- `global.v2ex.co/t/1223121` 是论坛主题页，包含动态内容和多条回复，不是单一商品或数值页面。

这些输入都不符合 Jev 更适合的形态：单页、单来源、单目标、明确数值。第一次失败后没有缩小输入范围，后续仍然重复使用宽目标和动态页，导致相同问题连续出现。

建议模板：

```text
startUrl: 具体商品或定价页，不使用首页、论坛列表或搜索结果页
goal: 读取该页某个明确产品的月付、包季、包年价格和币种
model: GLM-5.3
seller: 智谱官方或 Z.ai
specs: [{"name":"产品","value":"GLM Coding Plan 个人套餐"}]
```

## 2. 没有先用搜索确定 canonical URL

应该先用 `web_search` 做页面侦察，确认正式 URL 和页面类型，再把稳定的单页交给 Jev。实际调用直接猜 URL，导致第一条调用遇到跳转和 `no_progress`。

搜索结果只能用来发现来源或补充背景，关键价格仍需通过目标页面浏览和验证。

## 3. 同一来源并发调用，难以归因

同一轮同时对同一平台发起 `shopswarm_research` 和 `shopswarm_browse`，会产生竞争的浏览器会话，也无法判断失败来自页面、动作、网络还是调度。

正确顺序应是：

1. 一次只处理一个来源。
2. Jev 失败后，在同一来源切换到 `shopswarm_browse`。
3. 该来源确认无法继续后，再换下一个来源。

## 4. Jev 失败后离开 ShopSwarm 会话

`shopswarm_browse` 已经支持 `open`、`snapshot`、`waitText`、`click` 等动作。实际操作中只重复整页 `snapshot`，没有在同一会话内等待页面渲染，也没有点击套餐标签后再读取局部页面。

对于套餐页，应保持同一会话执行：

```text
open → waitText → snapshot → click(role, name) → snapshot
```

页面摘要被截断时，不应立即判定工具不可用；应使用可定位的控件和分段读取。

## 5. 另起第二套浏览器栈造成环境排错和证据断裂

任务中加载技能后自行寻找并启动 `agent-browser`，经历了：

- 命令不在 PATH；
- 找到旧版 0.13.0，命令能力不一致；
- 搜索多个 npx 副本；
- 遇到只读 socket 目录。

这些调用没有推进价格研究，还让 ShopSwarm 会话与外部浏览器会话的页面状态不再对应。ShopSwarm 已经提供 0.38.1 的浏览器后端，后续不应为同一任务另起浏览器栈。

## 6. 没有及时识别证据状态不一致

一次 DOM 读取找不到“连续包年”，但另一处摘要显示了“连续包季 8 折”。这表示当前标签页状态或读取上下文不可靠。实际却继续用算术推算包年价格。

遇到同一来源的状态不一致时，应立即：

- 在当前会话重新 `snapshot -i`，定位真实控件引用；或
- 回到 ShopSwarm 会话，使用 `click(role, name)` 切换标签后重新读取。

在状态没有重新确认前，推算值只能标为未验证，不能当作页面实测。

## 7. 登录墙页面的处理过晚

淘宝、闲鱼和部分中转站需要登录或会触发反爬。实际尝试了多次搜索和页面访问后才确认无法读取。

正确处理：

- 先判断是否需要用户已登录的 Chrome Profile；
- 用户允许复用并且已有登录态时，使用受控的已登录会话；
- 没有登录态时立即标记该来源为“未验证”，交回 Lead 或换公开来源；
- 不把空快照、登录页或反爬页面当作价格证据。

## 8. 证据和结论必须分级

研究结果至少分为三类：

1. **浏览器实测**：当前会话页面中读到，并能指出 URL 和控件状态。
2. **搜索或公开文章**：用于发现来源或补充背景，不能替代目标页面实测。
3. **推算或未验证**：由折扣、汇率或历史价格计算得到，必须明确标记。

交接给 Lead 时要说明来源、状态和缺失字段，不能只写“继续处理”。

## 9. 流程结论

这次任务的主要浪费不是浏览器速度，而是连续三次给 Jev 输入动态、多目标页面，失败后又离开 ShopSwarm 会话并启动第二套浏览器。后续按“搜索侦察 → 单页单目标 Jev → 同会话 browse 接管 → 明确证据分级”的顺序执行，可以减少重复调用，也能保留可复核的证据链。
