# M2.4 阶段验收：Coding Plan 首个真实领域

状态：已确认决策。确认日期：2026-09-23。

本文件记录 2026-09-23 当时的 M2.4 产品范围决策，并保留为历史验收依据。它不改写 M0—M2.3 已完成任务的历史验证结果。

> 后续范围已修正：ShopSwarm 当前目标是通用自然语言购物研究，Coding Plan 只是测试域之一。M3.2 及后续工作以 [产品范围：通用自然语言购物研究](产品范围-通用购物任务.md) 和 [真实购物任务与测试策略](../DOC/真实购物任务与测试策略.md) 为准。以下 1—12 条仍用于解释 M2.4 当时为何这样验收，不再作为未来产品边界。

## 已确认决策

1. ShopSwarm 的首个真实比价领域改为 **Coding Plan、LLM API 套餐和第三方中转套餐**。电商商品页不再作为首版默认真实验收场景。
2. 底层架构保持通用。模型、提供方和场景都来自任务输入；GLM-5.3 继续只作为测试样例，不写死到运行时。
3. 首批真实来源优先选择公开可读的官方价格页、Coding Plan 页面和第三方中转站套餐页。首版只读，不购买、不充值、不支付。
4. Jev 只负责从当前有效动作集合中选择导航动作和目标。Jev 不负责套餐价值判断、金额计算、额度换算或最终排序。
5. 页面字段由提取器提出候选证据，再由确定性检查核对。页面没有写出的价格、额度、缓存价、倍率、限制或续费条件保持未知。
6. Coding Plan 的核心身份至少区分提供方、套餐、模型或模型集合、计费方式、计费周期和价格语义。按量、包月、首购价、续费价和条件优惠不能混成同一口径。
7. 额度必须保留原始语义。Token、request、credit、5 小时窗口、周额度、月额度和模型倍率不能仅凭一个数字直接互换。
8. 后续通用完成条件改为字段驱动。任务区分必需字段与期望字段：必需字段全部有证据才允许成功；期望字段缺失时返回 unknown，不因缺失而无限浏览。M2.4 冻结规则，M4.1 实现通用领域接口。
9. 独立重开验证不仅核对对象身份，还要核对价格语义。至少保证提供方、套餐、计费周期、价格类型和适用条件没有变；如果仅金额发生变化，采用第二次可复核观察值并保留新的采集时间。
10. M3 的首批并行验收使用同一 Coding Plan 任务的至少两个来源。M4 的比较与排序优先实现 Coding Plan 数据契约，不再以商品规格和卖家作为主模型。
11. 真实站点失败、登录墙、验证码、频控或字段缺失都作为结果记录，不通过绕过风控来满足验收。
12. 当前 `ShoppingTaskContext`、`Offer`、`src/shopping/` 等名称是 M1/M2 已实现接口的历史命名。文档可以定义后续 `PlanOffer` 契约，但在代码完成前不能写成已实现。
