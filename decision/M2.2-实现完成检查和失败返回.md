# M2.2 实现完成检查和失败返回：已确认决策

日期：2026-09-23。对应任务：[M2.2](../TODO/done/M2.2-实现完成检查和失败返回.md)。

## 已确认选择

1. Jev 的 `DONE` 只是申请结束。ShopSwarm 独立检查任务指定型号、全部指定规格、卖家、币种、明确标价及每项页面证据。页面 URL 和采集时间必须保留。运费及优惠未查明时标为未知，不写确定到手价。
2. 第一次伪 `DONE` 把缺失项带回动作循环。页面和已核实进度均未变化时再次出现同样的伪 `DONE`，返回无进展，交给 DSH Agent 判断；不设一般性的任务级失败次数限制。
3. 登录失效、验证码只在页面或浏览器结果提供明确依据时分类。验证码不自动破解。登录失效结束本次任务，由 DSH 提醒用户在自己的 Chrome `Default` Profile 中重新登录；用户回复已登录后，按原任务条件新建会话、重新复制 Profile、重新核验，不轮询登录状态。
4. 失败结果区分已核实进度、尚缺字段、当前页面与原因。未核实候选可作为线索，不能放进已验证报价。
5. 每条成功报价均在新的隔离浏览器会话中重新打开商品 URL，必要时重新选择指定规格，再检查型号、规格、卖家和价格。重开后价格变化时以新观察为准；无法重现时不返回成功，交给 DSH Agent。
6. M2.2 接通 DSH 的单站工具与登录提示；M3.1 才接入多 Agent 分发。后续多站任务并发执行，Lead 等全部结果后同步汇总；单站失败不抹掉其他站结果。Jev 无进展或商品判断含糊时，站点 DSH Agent 负责下一步判断，但不能越过独立完成检查。

## 验证边界

重新打开商品页只能核实当时页面上的可重现报价，不证明结算价、库存持续性或商家履约。M2.3 才验证真实站点及登录复用；M3 才验证多站并发和局部失败。
