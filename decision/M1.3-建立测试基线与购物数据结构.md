# M1.3 建立测试基线与购物数据结构：已确认决策

日期：2026-09-23。对应任务：[M1.3 建立测试基线与购物数据结构](../TODO/in-progress/M1.3-建立测试基线与购物数据结构.md)。

## 已确认决策

1. M1.3.1 新增五类本地场景页面：搜索、规格选择、延迟加载、遮挡、失效元素，并规定启动、快照、单次动作三段耗时的记录格式。现有 `tests/fixtures/pages/browser-actions.html` 继续只给 M1.1 的动作测试用。至少 10 个固定任务、商品匹配与金额样例、真实站点仍归 Q.1。页面放在 `tests/fixtures/`，任务编号以后再与 Q.1 对齐。
2. M1.3.2 只固定报价载体，不把 M4 的匹配维度定成一等字段。`ProductIdentity` 是型号字符串加一组未解释的规格条目，每条规格只有名称和取值。`Offer` 包含卖家、币种、标价、费用项、页面 URL、采集时间，以及 `ProductIdentity` 和 `Evidence`。品牌、容量、颜色、地区版本、成色、套装是否同款，以及到手价计算，留到 M4。类型放在 `src/types.ts`，约定写入 `DOC/接口与数据结构.md`。该文档这一次只写这些类型，不写 `Task` 和 `browser_do`。浏览器类型仍留在 `src/browser/types.ts`。
3. 可以未知的值使用 `{ status: 'known', value } | { status: 'unknown' }`。金额在已知时是 `{ currency, minor }`，`minor` 为该币种的整数最小单位，人民币用分。未知运费或未知优惠写成 `unknown`，不用 `0`，也不用缺字段表示“看过但不知道”。M1.3 不做汇率、税费计算和到手价。
4. 耗时记录包含阶段名、耗时毫秒、命令、环境与版本、页面标识。测试只断言 `open`、`snapshot`、`action` 三段都被记下来，且耗时是非负整数。不把某一次的毫秒数写成通过阈值，也不把样本提交为会随机器变化的夹具。
5. 五个场景各自使用独立静态页，由 `tests/shopping-baseline.test.ts` 在 `127.0.0.1` 临时端口打开。通过条件是：搜索后快照出现包含查询的结果文本；选择规格后快照显示该规格已选、另一规格未选；延迟页第一次快照没有目标价格文本，固定约 300 毫秒后用现有文本等待条件可以等到；遮罩打开时被挡住的规格控件不在可访问树里，关闭后该控件出现并可点击；失效页在元素被移除后，用旧引用点击必须得到 `stale_element_reference`。失效判定继续使用 M1.1 的页面版本，不新增 DOM 节点消失检测。页面测试不从 DOM 抽取 `Offer`。
6. 具体类型按下面的形状。只有标价和费用金额使用 `KnownOrUnknown`。卖家、型号、规格条目、币种、URL 和采集时间写入时必须是已知字符串；页面上看不到卖家时，不造一条卖家未知的报价。规格只记录已经读到的名称和取值。`fees` 可以是空数组，表示这些费用还没被观察；“看到了运费但金额未知”写成 `{ kind: 'shipping', amount: { status: 'unknown' } }`。已知金额的 `currency` 必须等于 `Offer.currency`。证据对象直接放在 `Offer.evidence` 里，不做编号，也不做证据库。M1.3 的证据只有非空页面文本摘录，截图留给 M4.2。

```typescript
type KnownOrUnknown<T> =
  | { status: 'known'; value: T }
  | { status: 'unknown' }

interface Money {
  currency: string // ISO 4217
  minor: number
}

interface ProductSpec {
  name: string
  value: string
}

interface ProductIdentity {
  model: string
  specs: readonly ProductSpec[]
}

type FeeKind = 'shipping' | 'tax' | 'discount'

interface FeeItem {
  kind: FeeKind
  amount: KnownOrUnknown<Money>
}

type OfferField =
  | 'product.model'
  | 'product.specs'
  | 'seller'
  | 'currency'
  | 'listedPrice'
  | 'fees.shipping'
  | 'fees.tax'
  | 'fees.discount'
  | 'url'

interface Evidence {
  field: OfferField
  url: string
  observedAt: string
  excerpt: string
}

interface Offer {
  product: ProductIdentity
  seller: string
  currency: string
  listedPrice: KnownOrUnknown<Money>
  fees: readonly FeeItem[]
  url: string
  observedAt: string
  evidence: readonly Evidence[]
}
```

7. 三段耗时在测试里包住会话 `open`、一次 `snapshot` 和一次成功的元素动作来测量。不给 `BrowserActionResult` 增加耗时字段，也不在适配层里拆浏览器进程启动、CLI 传输和页面等待。那一段内部分解留到 M1.4.5。
8. 未知值由测试代码构造两条报价：一条标价和费用都已知，一条运费为 `unknown`。不新增 `tests/fixtures/offers.json`。匹配、条件价格和排序样例仍归 Q.1.2。
9. `src/types.ts` 导出纯函数 `validateOffer(input: Offer): void`，失败时抛出带字段路径的 `Error`。`src/index.ts` 导出这些类型和该函数。规则是：`model`、`seller`、`currency`、`url`、`observedAt`、规格名称和取值、证据的 `url`、`observedAt`、`excerpt` 都是非空字符串；`currency` 只要求三个大写字母，M1.3 不做币种表。`specs`、`fees`、`evidence` 都可以是空数组。同一种 `FeeKind` 在一条报价里最多出现一次。`minor` 必须是安全整数，已知金额的币种必须等于报价币种。不要求每个已知字段都有对应证据。全部已知的样例要带一条 `listedPrice` 证据；运费未知的样例不为这条未知运费配证据。证据与字段的强制对应留到 M4.2。
10. 页面路径为 `tests/fixtures/pages/baseline-search.html`、`baseline-spec.html`、`baseline-lazy.html`、`baseline-overlay.html` 和 `baseline-stale.html`。浏览器五场景和报价校验放在同一个 `tests/shopping-baseline.test.ts`。耗时记录类型只放在这个测试文件里。阶段名用 `open`、`snapshot`、`action`。`command` 记录实际调用，例如 `open`、`snapshot`、`click`。环境和版本记录 `process.version`、`process.platform` 和已安装的 `agent-browser` 版本。
