# 产品范围：通用自然语言购物研究

状态：已确认决策。确认日期：2026-09-23。

本文件修正 M2.4 之后的产品范围。它不改写 M0—M3.1 已完成任务的历史验证结果；其中 Coding Plan / LLM 套餐相关记录继续作为已经做过的一组测试。

## 已确认决策

1. ShopSwarm 的产品目标是**通用购物与价格研究**，不是 Coding Plan 专用比价器。
2. 用户入口以自然语言购物意图为主，例如“帮我找一台 27 英寸 2K 显示器并比较价格”，也可以是“比较几个 Coding Plan”。商品类型、平台和来源不在产品层写死。
3. Coding Plan、LLM API 套餐和第三方中转套餐是测试域之一。GLM-5.3 仍只是固定测试用例之一。
4. DSH / Lead Agent 负责把自然语言意图拆成候选来源、待核对条件和子任务；ShopSwarm 的浏览器、Jev、证据、验证和比较层保持领域无关。
5. 单来源工具可以继续保留 M1/M2 的 `model + specs + seller` 兼容接口，但后续通用任务契约不能以这些字段作为产品边界。
6. M4 优先实现通用 `ResearchTask` / `Offer` / `Evidence` / comparability 能力；Coding Plan 的 priceType、quota、billing period 等作为领域扩展或 fixture，而不是核心类型的唯一形状。
7. 端到端测试必须覆盖多个真实购物域。至少包含一个数字服务/套餐类用例和两个非 Coding Plan 的实体商品或消费品用例，并跨多个公开来源。
8. 真实 E2E 优先选公开可读、无需登录、风控较低的页面。遇到登录墙、验证码、频控或明显反自动化限制时，记录为来源失败或阻塞，并换用其他测试来源；不把绕过风控作为 ShopSwarm 的能力或验收条件。
9. 测试结果只证明“这个任务在这个来源、这个时间点是否成功”，不能把单个站点失败推导成某类购物任务不支持，也不能把单个站点成功写成“支持所有平台”。
10. 首版仍只做研究、读取、验证和比较，不自动下单、支付或充值。

## 对现有规划的影响

- M2.4 与 M3.1 的 Coding Plan 记录保留为历史验证。
- M3.2 起，多来源关联与失败处理按通用购物来源设计。
- M4 不再以 `PlanOffer` 作为唯一目标模型。
- Q.1 的真实 E2E 从“两个 Coding Plan 来源”扩展为“多领域、多来源”矩阵。
- M5 的支持声明按实际通过的任务类别和来源记录，不以 Coding Plan 覆盖率代表产品范围。
