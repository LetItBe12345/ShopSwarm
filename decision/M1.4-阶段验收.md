# M1.4 阶段验收：已确认决策

日期：2026-09-23。对应任务：[M1.4 阶段验收](../TODO/in-progress/M1.4-阶段验收.md)。

## 已确认决策

1. M1.4 在 M1.3 的本地固定页面上验收，不调用真实模型，也不打开京东或天猫。环境沿用 M0 已确认的 Ubuntu 24.04 x86_64、Node.js 24.21.0、pnpm 11.7.0 和 agent-browser 0.38.1。
2. 基础动作沿用 M1.1 已确定的打开、快照、点击、填写、选择、按键、滚动、等待、后退和关闭。同一套动作连续成功 3 次才算 M1.4.1 通过。故意使用失效元素引用时，必须返回明确失败原因。
3. M1.4.2 同时打开两个会话和不同页面。关闭其中一个后，另一个仍只能操作自己的页面。
4. M1.4.3 在正常退出和取消之后，本项目拉起的浏览器进程和临时 Profile 都不残留，也不关闭验收开始前已经存在的外部会话。
5. M1.4.4 由验收过程在临时目录生成带标记 cookie 的专用 Profile。该 Profile 不读取用户正在使用的 Chrome，也不放入仓库。agent-browser 只操作它的副本。标记 cookie 必须能从副本读到；原 Profile 的文件内容必须与测试前一致，内容变化则本阶段失败。
6. 真实店铺是否仍保持登录，以及快照模式是否抢走前台焦点，只记入兼容性记录，不阻断 M1 完成。未验证的登录复用不写成支持承诺。真实站点登录 Profile 留到 M2。
7. M1.4.5 把耗时拆成浏览器启动、单次 CLI 调用和页面等待三段。只要求三段能够分开记录，不设时延上限。

## 后续边界

- 登录态和焦点的实测结果在验收执行后写入 `DOC/兼容性与支持范围.md`。
