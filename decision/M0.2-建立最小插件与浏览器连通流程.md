# M0.2 建立最小插件与浏览器连通流程：已确认决策

日期：2026-09-23。对应任务：[M0.2 建立最小插件与浏览器连通流程](../TODO/done/M0.2-建立最小插件与浏览器连通流程.md)。

## 已确认决策

1. M0.2 建立私有 TypeScript 包 `shopswarm`，暂不确定公开 npm 包名和许可证；发布准备留到 M5。
2. Bundle 使用根目录 `cordis.patch.yml`，以 DSH 外部 Bundle 方式加载 `shopswarm` Host Plugin，不修改 DSH 源码。
3. 最小工具名为 `shopswarm_diagnose`。它验证运行版本、调用身份、XDG 路径和可选的浏览器连通，不提前定义购物任务的数据结构。
4. 浏览器连通验证使用本地固定页面和无登录的独立 agent-browser 会话，不访问真实购物站点，也不读取用户 Chrome Profile。
5. 创建浏览器前必须从 DSH 执行上下文取得 Agent 身份。会话名由 Agent 身份与调用编号派生，模型参数不能指定资源归属。
6. 默认配置、状态和缓存目录分别使用 `~/.config/shopswarm`、`~/.local/state/shopswarm` 和 `~/.cache/shopswarm`，并遵循 XDG 环境变量。
7. 项目检查命令定为 `pnpm check`，包含类型检查、单元测试和构建；浏览器连通检查单独使用 `pnpm smoke:browser`。
8. 本阶段提供最小 `shopping-research` Skill，只描述已经实现的诊断能力。用户最终仍以自然语言提出购物任务，测试品类和站点只限定验证范围，不构成运行时白名单；完整分发规则在 M3.1 实现。

## 仍需后续验证

- M1.2 验证复制 Profile、登录态、后台运行、焦点变化和异常清理。
